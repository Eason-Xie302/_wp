## 2. 📝 AI 協作開發紀錄與邏輯碰撞懶人包

本專案為全 AI 協作與人類開發者深度討論之成果。在開發本專案的過程中，本人與 AI 針對系統架構、演算法節奏、非同步控制進行了多輪密集的技術碰撞。以下為核心開發歷程摘要 (TL;DR)：

1. **技術架構大升級（Node.js 後端整合）**：原計畫採用純前端靜態網頁實作，為符合課程對於伺服器端的硬核指標，決議進行架構重構。在 AI 協助下，以標準 Node.js + Express 伺服器架構重組，建立 `public` 靜態資源隔離區與 `server.js` 路由派發主程式，並補全 `package.json` 依賴管理，完全符合業界規範。
2. **UI/UX 排版與動態網格修正**：初期 JavaScript 動態渲染網格時，因 CSS 屬性脫鉤導致網格排列異常。後續導入 CSS Grid 佈局，並透過 JavaScript 監聽難度變更事件，動態修改 `grid-template-columns`，結合 `aspect-ratio` 維持完美正方形，重構為現代化 Fluent Design 風格介面。
3. **硬核遊戲機制與非同步時間管理調度**：
   * **盲解模式**：利用前置 3 秒倒數計時作為記憶緩衝，實作點錯懲罰（總時間強灌 +1 秒），並利用 `setTimeout` 精確調度點錯時全場「閃現 0.5 秒」的記憶補救機制。
   * **隨機互換模式**：為提升挑戰性，設定為每 1.5 秒觸發一次，由演算法動態計算畫面上剩餘未點擊的方格，隨機挑選多組數字進行同步位置對調。
4. **環境工程與本地部署除錯**：排除 Windows PowerShell 的 ExecutionPolicy 權限阻擋，並將伺服器監聽 Port 轉移至 `8080`，成功解決與先前開發專案的通訊埠衝突問題。

## 3. 專案簡介與啟動方式

### 專案簡介
本專案為經典專注力訓練遊戲「舒爾特方格」的現代化網頁重製版。支援 3x3 至 7x7 的動態難度切換，並獨創兩項硬核遊戲機制：
* **🌪️ 隨機互換模式 (Chaos Mode)：** 系統每隔 1.5 秒會自動抽取多組方格進行位置互換，極大化考驗動態追蹤能力。
* **👁️ 盲解模式 (Blind Mode)：** 遊戲啟動後數字隱藏，點錯即給予 1 秒懲罰，並觸發 0.5 秒的全局閃現作為記憶補救。

### 啟動教學
請確保您的開發環境已安裝 Node.js，接著於終端機執行以下指令：

```bash
# 1. 安裝專案所需依賴
npm install

# 2. 啟動 Node.js 後端伺服器
node server.js
```
伺服器啟動後，請開啟瀏覽器並前往：http://localhost:3001 即可開始遊戲。

## 4. 技術棧與系統架構

### 後端 (Server-side)

* **Node.js + Express**

  * 負責靜態資源派發與路由隔離。
  * 提供本地伺服器環境以支援專案執行。

### 前端 (Client-side)

* **Vanilla JavaScript (ES6+)**
* **HTML5**
* **CSS3 (Flexbox / Grid)**

  * 負責遊戲邏輯、介面渲染與響應式版面配置。

### 資料持久化 (Data Persistence)

* **HTML5 Web Storage API (localStorage)**

  * 儲存各難度的歷史最佳成績排行榜。
  * 實現本地端資料保存功能。

## 5. 核心技術亮點

### DOM 操作優化與 Event Delegation

* 利用事件委派機制綁定父層容器。
* 大幅提升高數量方格下的點擊監聽效能。
* 降低記憶體消耗並提升程式維護性。

### Fisher-Yates 洗牌演算法

* 採用業界標準 Fisher-Yates Shuffle。
* 確保每一局方格數字分布具備均勻隨機性。
* 避免因排序法造成的機率偏差問題。

### 非同步狀態與 Timer 調度管理

* 運用 `setTimeout` 與 `setInterval` 控制遊戲事件。
* 精準調度盲解模式與隨機互換模式。
* 嚴謹處理 Timer 清除機制，避免狀態衝突與記憶體洩漏。
